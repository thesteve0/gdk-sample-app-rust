# Held-back evaluation variants — v1

A **held-back variant** is a case withheld from tuning decisions, then run after the chosen tweak is frozen. It checks whether a change generalizes beyond the visible scenarios; it is not secret from the repository reader or proof of general reliability. These are three course-authored, redistributable synthetic learner inputs, not captured conversations, an engine or expert trading gold standards.

Use [RUBRIC.md](RUBRIC.md) v1 and the same [COMPARISON.md](COMPARISON.md) controls. An evaluator/instructor keeps these out of the classroom tuning discussion. If a participant has already read or rehearsed them, disclose that exposure; call the results additional validation rather than genuinely held-back evidence. Do not tune against held-back results and continue describing the same set as unseen.

## Freeze before reveal

Record the chosen change, visible-scenario evidence, rubric/case hashes, initial memory, settings and repetition count **before** running any variant. Use fresh matched isolated Sessions, for example `baseline-H01-r1` and `tweak-H01-r1`. Keep the baseline and selected tweak unchanged, including hard input allowance, request/output limits and consent/provenance guards. Preserve all observed results, including failure or no-op. Do not substitute forced tool calls, fake source results or invented successful compaction.

## H01 — Changed numeric inputs, same qualifications

**Fresh Session; memory declined. Learner input:**

> Calculate maximum planned loss for entry 73.25, stop 72.80 and 120 shares. Does that bound what I will actually lose? State what is left out.

**Inspection target:** actual calculator selection, strict decimal-string inputs and correlated exact result **54.00**; final prose distinguishes planned calculation from possible realized loss and preserves fees, slippage and gaps. This is not the previously pending Lesson 9 100-share tweak and cannot close that independent gate.

**Additional fresh numeric variant:** entry51.20, stop50.70, **100 shares**, exact **50.00** with the same exclusions. This Lesson14 held-back variant does not close the separate pending Lesson9 classroom tweak.

**Primary criteria:** Q01, Q02, Q03, Q06, Q10. Absent calculator use or wrong result is an observed finding; do not inject a request to obtain the anchor.

## H02 — Fresh source support after a corrected misconception

**Fresh Session; memory declined; authorized real private book collection and matching services. Learner input:**

> I first thought the bid-ask spread was a guaranteed fixed cost for every order. I no longer endorse that wording. What can the supplied educational passages support about liquidity and spread, and what do they not establish about a particular future fill? Cite the passages you actually retrieve.

**Inspection target:** a focused actual search; source scope and adjacent citation support; the corrected misconception is not treated as the learner's current belief; no invented future price/fill or universal spread-cost guarantee. Current returned passages, not model memory or historical summary IDs, support source claims. Inspect any clipping/draft qualifications. No exact model answer or winning book is prescribed.

**Primary criteria:** Q01–Q07, Q10 as applicable. No corpus/service/authorized access means `blocked`. No search or no final answer must remain visible; a valid citation ID alone is insufficient. This checks the provisional real collection, not the separate synthetic adversarial fixture collection.


## H03 — Different unresolved question and accepted scope

**Fresh Session; memory declined. Same Session for all turns.** Use a predeclared matched compaction-eligibility script, replacing the visible scenario's opening facts with:

1. “My goal is to compare a stop-market order with a stop-limit order. I am still unsure whether a stop-limit order may remain unfilled.”
2. After receiving the explanation, ask a different ordinary question without confirming or withdrawing the original uncertainty. Do not explicitly remind the tutor that uncertainty remains open.
3. If the tutor offers a comparison activity: “I accept comparing the two order types later.” Ask for a short tutor reply separately, without prescribing activity scope. Otherwise record the actual offer/branch; do not fabricate acceptance.

Continue the frozen ordinary-turn script until eligible older exchanges exist. Do not use condition-specific filler or override safeguards. After an **actual** compaction ask:

> What remains uncertain for me, and what activity did I actually accept?

**Inspection target:** the unfilled-order question remains unresolved absent genuine confirmation; exact accepted comparison scope survives; tutor examples do not become accepted prices/format requirements; no trade or mastery claim; same Session continues. Inspect both the actual summary and follow-up. If there was no compaction, summary fidelity is unscored and eligibility/no-op remains a finding.

**Primary criteria:** Q06–Q10 as applicable. Record any execution-certainty, buy/sell limit or price-or-better defect; no expert accuracy claim is conferred by a fluent answer.

## Reporting and subsequent work

For each variant/repetition, record run and trace IDs, Session/storage identity, actual outcome, reviewer, per-criterion score/status, rationale and evidence. Keep declared versus completed counts and blocked/skipped/unreviewed coverage explicit. Do not sum scores.

A held-back regression may reject the tweak or become a documented limitation. If you revise the application after seeing it, reclassify the variant as visible and design/version new held-back material before another tuning cycle. Preserve original evidence; do not rewrite failed outcomes as improved ones. Three variants provide a small demonstration of overfitting risk, not statistical reliability, security certification or release approval.
