## Concepts introduced

A **local learning declaration** is the learner telling the application that they consider a named concept learned. Here `/learned <concept>` records that declaration when memory is enabled. It is **not** evidence of mastery, a test result, completion of a required progression, or readiness to trade. The command is handled locally, not interpreted as a model tool request.

Keep **three state domains** distinct:

| Domain | Purpose and authority |
| --- | --- |
| Authoritative application state | Actual message identities/provenance, exact learner statements, tool correlation, approval decisions, revisions and limits. Exact wording establishes who said what, not whether a belief is true or a category is correct. A generated summary cannot change these facts. |
| Learner-authorized persistent record | Selected notes in `learner-record.md`, used only with per-selection consent. Ordinary model proposals still need separate local approval. |
| Model working context | Instructions, consented record context, tools and conversation information supplied for inference. It can be shortened without silently changing the other domains. |

A **context window** is the bounded input a model can consider in one inference. **Working context** is the information our application supplies for that inference. **Lossy compaction** replaces selected older conversation material with a shorter generated summary: details can be omitted or distorted. It is neither an exact archive nor a guarantee of true claims.

**Genuine learner provenance** means a statement came from an actual learner reply, with its original identity and role. A summary quoting that reply is derived text, not a second genuine reply. Book excerpts, tool output, application opening messages and local commands are not eligible learner quotations.

An **exact learner-statement archive** is bounded, in-Session storage of accepted genuine learner messages and their original IDs outside lossy working history. It preserves original wording when summaries omit or distort it. It is neither the persistent learning record nor a generated summary; it is not a full transcript of tutor replies and does not classify understanding, agreement or question resolution. Its prompt projection contains only originals no longer present in retained history, as untrusted historical data.

A **safe boundary** is a point where an older complete exchange can be replaced without splitting pending tool work or disrupting current-turn inspection and local approvals. An **exchange** starts with one genuine learner reply and includes its completed tutor attempt(s), application reminder if needed, and correlated tool requests/results. Both attempts belong to that same genuine exchange. Pair validation uses each protocol kickoff window, so a calculator ID may be reused across attempts without splitting or confusing either pair. Requests and responses must remain together.

An **Operation** is a GDK decision unit that examines state and proposes work. An **Effect** describes a change that the application runtime applies. The compaction Operation prepares a replacement; its replacement Effect changes working history only after validation. An **Event** is live presentation activity, not that saved change. GDK still owns re-evaluation through `StateMachine::run`; this application supplies the policy, not full Goose's automatic compaction assembly.

A **revision** identifies the state version used to prepare a replacement. Checking it before applying prevents a stale summary from overwriting intervening changes. A **budget** limits resources the application will use; this lesson uses a conservative byte estimate, not a verified model-token capacity.

A **token estimate** is an informational approximation of the full active model working context, not a tokenizer measurement. The supplied display counts UTF-8 bytes in the serialized messages/tools projection produced by the OpenAI formatter, divides by four and rounds up. It uses the selected model's formatting and configured thinking-replay behavior, including whether replay is enabled and any model-specific preservation format. This is neither an exact token count, an upper bound nor an actual wire-byte count. It is separate from conservative byte safety budgets and cumulative provider usage; it does not show a context-window percentage or remaining tokens.

A **Session activity plan** is bounded, temporary application-owned state recording exact activity scopes and learner-confirmed statuses. A scope describes what the learner chose, without invented requirements. **Accepted** means locally added, **Selected** means the one currently chosen activity, **Completed** means a learner-confirmed status, and **Cancelled** means retired from active use. None means independently assessed understanding. Ordinary discussion, saved notes and generated summaries cannot make these transitions.

A **candidate source mapping** places a citation-adjacent answer passage beside identifiable lines of the supplied excerpt for human inspection. It establishes text identity and position, not that the passage supports the answer. **Semantic support** asks whether the evidence justifies the actual claim, including conditions, negation and scope. **Attribution completeness** asks whether all source-derived claims needing citations received adequate ones. **Causal faithfulness** asks whether the cited material actually informed generation; a plausible matching citation alone cannot establish it. **Current applicability** asks whether a source claim remains appropriate in the present setting. These are different questions.

A **course reference check** is supplied authored conceptual guidance with public primary references, not another model's judgment of the preceding answer. A **provisional stream** is model text shown before independent verification; a later notice cannot undo text the learner has already read.

## 13.0 — Carry forward Lesson 12 grounding

A **grounding attachment** is the selected book evidence for one genuine learner question, kept separately from conversation history. Before recording that question, the application performs one retrieval: default similarity threshold **0.55**, at most **three excerpts**, **2,500 tutor-token serialized search-response budget**, and **1,000 tutor tokens per excerpt**. These token limits are distinct from compaction's byte estimate. The threshold is provisional, not a relevance or truth guarantee. Kickoff, blank input and local commands do not trigger this question retrieval. The model cannot elect to skip it or request arbitrary SQL/search.

A **partially supported answer** uses what an excerpt establishes for one relevant part while distinguishing remaining background; it need not discard evidence because it cannot answer everything. Attribution identifies a source claim rather than endorsing it as current fact or a learner instruction.

An **acknowledgment** is a visible citation or explicit decline of supplied excerpts. `ChatSession::prompt_parts` places the authored source-grounding contract first. A grounded answer must cite used excerpts with their exact `[source:<id>]` markers, or state that they did not support the answer with `[source:none]`. Evidence replaces the previous question's attachment and is not appended as a learner message. The current prompt asks the tutor to use supported portions, qualify dated claims and decline only when no relevant part is supportable; application acknowledgment checks still cannot verify that judgment.

An **attempt** is one bounded GDK run for the current question. An **invalid acknowledgment** has malformed/incomplete marker syntax, a stale or unknown ID, a cite-plus-decline contradiction, or an empty/malformed decline. A valid decline requires one standalone nonempty explanation ending in the exact `[source:none]` marker; the application checks structure, **not** whether its limitation is specific, justified or true. `Cited` requires at least one exact current supplied ID with no invalid markers, not citation of every supplied excerpt.

`run_turn` classifies a successful final answer through `grounding_outcome`. Both `SilentIgnore` and `InvalidAcknowledgment` receive **at most one** application-authored reminder and a second attempt using the same evidence and fresh attempt bounds. No third attempt occurs even if acknowledgment still fails. `NotSupplied` never retries, including when an ungrounded reply has stray markers; a structurally proper explicit `Declined` does not retry. Errors/incomplete attempts cannot approve or escalate. Before the reminder, the application settles first-attempt proposals; `append_application` adds neither a genuine learner ID nor an archived learner statement.

A **source-use report** is application-owned diagnostic data recording lexical source use, not model self-assessment. `source_use_report` lists **every supplied ID** as `cited` or `not cited`, actual decline prose, unknown IDs, malformed-marker/decline-structure/contradiction diagnostics and the retry classification. It adds no excerpt bodies. Unused passages are not proven irrelevant; similarity, exact IDs and fluent decline prose do not establish semantic support. This report is not a quality score or a claim that teaching execution/source semantics are solved.

## Exact continuity without new authority

Compaction used to leave older learner wording recoverable only through a fallible summary. The archive now preserves accepted genuine learner text and IDs **exactly**, in original order, outside that lossy history. This is in-process Session continuity, not a disk save or consent to persistent memory. Opening messages, tutor text, tools, summaries, application reminders and local commands are not archive entries.

The archive holds at most **256 statements and 32,768 serialized JSON bytes**, including original IDs, UTF-8, JSON syntax and escaping—not just raw text length. `check_learner_capacity` checks a non-mutating candidate **before retrieval or maintenance**; the real append repeats the check atomically with the full input-budget check. `PendingReply` is counted prospectively but is not archived early. Refusal preserves stored state; there is no eviction, truncation or silent forgetting to admit another reply. When full, start a fresh selection rather than raise the caps as a classroom exercise.

A **continuity projection** is the prompt view of only archived originals absent from retained history, matched by original ID. Recent retained messages are not doubled. After compaction it carries the exact omitted learner wording as explicitly untrusted historical data; it outranks a summary only about **who said what**. It assigns no machine-verified category, truth, mastery, closure, agreement, current preference or write permission. An ambiguous “yes” whose tutor referent is absent requires clarification, not a fabricated activity. Later genuine corrections outrank earlier wording. The summarizer still reads only eligible stored historical messages, not this archive or a pending reply.

After defining that distinction, inspect this supplied fragment in `ChatSession::prompt_parts`; it adds data without rewriting conversation history:

```rust
if let Some(part) = self.learner_statements.prompt_part(&self.conversation) {
    parts.push(part);
}
```

Both the hard input budget and informational context estimate include this active projection. Moving originals out of history therefore does not make all their input cost disappear: exact continuity, static instructions and protected recent history form an **irreducible floor**, the input that compaction cannot remove under this policy. Gains may shrink or a candidate may no longer meet the reduction/fit checks. No unlimited conversation, automatic semantic recovery or guaranteed compaction gain is promised.

**Memory remains a narrower boundary.** Every model-proposed `note` must equal `learner_quote` verbatim in **all categories**, quoting part of the latest genuine learner reply in the current exchange. A reminder attempt may still quote that same real reply, not the reminder. Neither an older retained reply, the archive nor a summary is a new proposal source. Main checks this provenance before the supplied `validate_verbatim_note(&proposal)?;` equality check. Equality prevents paraphrased additions, but a verbatim question can still be miscategorized as an activity. The local prompt explicitly asks the learner to inspect category and usefulness with **default no**; successful run/inspection, independent approval, decision log, append and Session refresh remain mandatory. The proposal tool still never writes.

**Saved options are not new commitments.** After consent, the application—not a hoped-for tutor welcome—shows top-level saved notes under recognized `## Learner-agreed next activities` headings as options. It warns they may be outdated: nothing is selected, completed or executed, and no write follows from showing them. The helper does not guess activities from arbitrary hand-edited formats or nested quotation lines; unrecognized formats simply produce no inferred option list. Learners can choose a topic or request a correction; hand-edit rules remain unchanged. This display does not repair historical summary, source-use or teaching errors.


## What research can—and cannot—fix

This section explains why the supplied safeguards are deliberately narrower than “a reliable tutor.” The public research review was checked through **2026-11-12**; it is a targeted primary-source review, not an exhaustive systematic review or a test of this local model. Some papers below are preprints. No inspected study establishes a general fix for this application's open-ended source interpretation, learner-state inference or teaching. That is **not proof that improvement is impossible**. Task-specific training, clearer objectives, inspectable evidence and explicit human decisions can reduce risks; this application still needs actual validation and qualified review.

| Failure family and synthetic example | Research evidence and application response | What remains unproved |

For scale, LongTutor's structured math benchmark reports **97.0% basic extraction** but a best diagnosis **39.7 macro-F1** (a class-balanced diagnostic metric, not a learning score). Tutor CoPilot's inspected v3 reports human-tutor-assisted session exit-ticket passes **62%→66%**, with no significant end-of-year math benefit. Bastani et al. report improved assisted practice but **17% worse unassisted scores** for their GPT Base arm; the guarded Tutor arm was not significantly different from control. These results concern particular studies and settings, not expected outcomes for this financial-education application. They explain why we separate retained evidence, tutor behavior and independently observed learning.

The retrieval cutoff **cosine similarity 0.55 is neither 55% confidence nor an instruction to cite**. Cosine similarity ranks candidate text; it does not establish support. A partially relevant excerpt may support one part of an answer but not another. A legitimate decline remains possible; a syntactically valid `[source:none]` does not establish that declining was justified. Conformal-RAG illustrates calibrated filtering under explicit annotation/distribution assumptions; this course has neither that calibration nor a conformal guarantee. Do not force citations to make a display look successful.

### Observe exact local activity authority

The plan accepts at most **16 entries**, each exact scope at most **600 UTF-8 bytes**, and at most **8,192 serialized JSON bytes** total. It does not evict entries to create room. It is ephemeral: a fresh selection starts a fresh plan, while continuation and safe compaction/revision preserve the same Session's confirmed state. It never auto-runs an activity, writes memory or assesses mastery. A local completion declaration is not evidence that work was performed correctly.

All changes use an explicit **default-no local confirmation**, displaying the exact scope and proposed transition. Saved-option numbers and Session activity IDs are different namespaces: `/activity saved N` resolves a recognized consented option into a proposed local Add; loading memory or approving a note does not itself add anything. Add does not Select. Only one entry can be Selected; selecting another returns the former selection to Accepted. Complete applies to the selected activity; Cancel retires an active activity. No tutor tool or ordinary chat reply can make these transitions.

Predict, then observe the normal command path with your own genuinely wanted scope. This is **synthetic command syntax**, not a claimed live transcript:

```text
/activity
/activity add Compare a buy limit order with a stop-market order using one hypothetical example.
/activity list
/activity select 1
/activity complete 1
```

The plan is displayed on explicit `/activity` or `/activity list` requests and after confirmed activity changes, not after the welcome or every ordinary exchange. Its full rendering remains in private diagnostics after each completed exchange.

Inspect each proposed transition and answer its local confirmation yourself; Enter/default no leaves state unchanged. IDs shown here assume an otherwise empty plan. If a different accepted activity is no longer wanted, inspect `/activity cancel N` instead. With consented saved options, `/activity saved N` proposes adding that option and still requires confirmation. Do not add an unwanted activity just to exercise a branch. To start the actual discussion after selection, send an ordinary learner question: selection itself does no teaching work.

### Inspect sources without asking a model to grade itself

After a genuine question completes, use:

```text
/sources
/sources 1
/checks
```

`/sources` lists the **current selected attachment** (at most three excerpts), lexical usage and acknowledgment information without printing excerpt bodies. `/sources N` prints only the selected current excerpt requested, its source metadata (file basename, pages, recorded document/chunk hashes and review/truncation status), exact supplied-excerpt line ranges, and the answer paragraphs adjacent to matching citations. It makes **no extra search or model call**. Source text can be private: inspect locally, not on an unapproved projector or in a public bug report.

A **UTF-8 byte range** identifies positions in encoded text, not character numbers. These zero-based, end-exclusive ranges refer to the **original supplied excerpt**, not PDF coordinates, original full-chunk offsets or a reviewed supporting subspan. The display identifies line bodies and separators; sanitizing terminal control characters does not redefine the original offsets. Recorded hashes identify the document/full chunk, not necessarily a truncated excerpt. Citation-adjacent answer ranges identify candidate passages for comparison, **not an extracted list of every factual claim**. Inspect quantities, conditions, negations and historical modality yourself. The application does not certify support, completeness, current applicability or causal faithfulness.

`/checks` shows authored course reference material, not a semantic checker of the last answer. It covers submission/trigger/execution, conditional limit-price protection, quotes/spread versus fills, simulation assumptions, maximum planned loss versus realized loss, historical advice and the distinction between references and understanding. For example, a buy limit constrains price **if execution occurs**; it does not promise a fill. The calculator's `(51.20 − 50.70) × 200 = 100.00` is maximum **planned** loss under its assumptions, not a realized-loss ceiling. No domain-expert certification, current broker/venue/simulator validation or exhaustive rulebook is claimed.

These annotations are self-contained reasons to read further, not prerequisites for understanding the implementation. Dates identify the inspected publication/version, not a claim that every paper is peer-reviewed. Results do not transfer automatically between models, domains or user populations.

## 13.3 — Explain the replacement boundary

The application retains the original opening and the **latest two complete genuine learner exchanges**, including their tool pairs, original message IDs and metadata. It summarizes only eligible older history. At later compactions, the previous summary and newly eligible history produce **one replacement summary**, not an accumulating stack of summaries.

An optional **pending reply** is the upcoming genuine question and its selected grounding attachment, not yet recorded in history. `PendingReply` makes prospective maintenance count that question and replacement attachment before and after compaction. It does not make either item summary source material: isolated summary input contains only eligible historical messages, never the pending question or current evidence. `append_grounded_user` then validates a candidate containing both question and attachment before atomically changing stored history/evidence/genuine IDs and revision. A refused append leaves those unchanged. After defining the pending reply, inspect this focused argument from main's automatic `compaction::maintain` call:

```rust
Some(compaction::PendingReply {
    input: input.clone(),
    grounding: grounding.clone(),
}),
```

Then follow `append_grounded_user` to its candidate-budget check **before** any stored assignment. This order prevents a newly appended question from falsely becoming an incomplete historical exchange during maintenance.

The summary is assistant-derived, fallible **data**, not a genuine learner message or higher-priority prompt instruction. Common instructions, teaching guidance and consented record context stay separate. Summary generation uses a **tool-free isolated inference coordinated through the GDK**: it cannot search, calculate, propose notes or authorize writes. Its generated text is checked before the replacement Effect is applied.

The summarizer now receives an **ordinary-content projection**: a temporary input view with original message IDs, speaker roles and explicit provenance labels. Genuine learner replies are identified using application-owned reply IDs, not user role alone. Tutor text is labeled as explanation, prior summaries as fallible derived data, and tool requests/results as correlated historical data. Provider reasoning, redacted reasoning and internal message metadata are excluded from this view; originals remain unchanged in stored history and diagnostics. The projected request plus source-boundary instructions and editable guidance is checked against the same input allowance.

Summary guidance requires unresolved uncertainty to remain last expressed uncertainty unless a later genuine learner explicitly confirms resolution or withdraws it. Tutor answers alone cannot close it. Accepted activities preserve the learner's exact accepted scope; tutor reply length and hypothetical example prices cannot become activity requirements. These labels and checks enforce input provenance, not the semantic truth of every generated sentence.

The application sets a **pending maintenance request**: recorded intent to do context maintenance instead of tutor work. This separate run contains only the compaction Operation, so completion yields to the learner prompt without an unsolicited teaching response. A **replacement candidate** is prepared history that has not yet changed the store; the runtime applies it only at the expected revision. These are supplied application types, not new SDK APIs. The focused effect boundary is:

```rust
Maintenance(compaction::Outcome),
```

The outcome carries the expected revision, optional replacement conversation and an honest report. A no-op or failed attempt has no replacement; the report and available usage are still recorded. Locate `apply_outcome` in the supplied compaction module to see the revision check before conversation replacement. The application-owned completion/approval ledgers and cumulative usage remain outside generated summary authority.

The SDK exposes conversation replacement, but this custom runtime must explicitly implement its own safe replacement behavior. After explaining Effect, inspect this focused enum variant from pinned `goose-agent = 0.1.0-alpha.11`:

```rust
ReplaceConversation(Conversation),
```

This is an SDK capability, not a complete compaction policy or an instruction to insert the variant into an arbitrary application enum. In the supplied source, locate the compaction Operation, isolated inference, revision check and runtime replacement together. Narrate: choose eligible history → prepare bounded summary → validate replacement and revision → apply Effect → GDK reloads/re-evaluates. Supplied async machinery is infrastructure to explain, not reconstruct in class.

If preparation, validation or revision checking fails, the original working history remains intact. A successful replacement must reduce the measured working input; shape/size checks cannot prove that its meaning is faithful. Pending work is not split or discarded to make it fit.

**Quotation boundary:** a model proposal may quote only part of the latest genuine learner reply in the current exchange, including a subsequent reminder attempt. It may not quote an older retained reply, the exact archive, summary, tool response, opening, reminder or command. The note must equal that quotation verbatim. Archiving original wording preserves continuity, not eligibility or write authority.

**Citation boundary:** historical passage IDs in a summary are reminders of past evidence, not current citation support. Each later genuine learner question triggers a new retrieval before append; only that question's selected attachment can support its current citations. A valid old ID cannot substitute for the actual returned excerpt, its clipping and source qualifications.

## 13.4 — Observe the conservative budget

The supplied application policy is:

| Boundary | Supplied policy |
| --- | --- |

## Pre-display citation gate and fabricated-reference rejection — 2026-11-12

After a live run showed the tutor citing `[source:<id>]` markers the application never supplied, the application now gates every tutor reply **before the learner sees it**:

- **Buffered display.** `display_events` buffers the complete streamed reply into memory and returns it; nothing is printed during the run. The comment in the code says it directly: "The reply is buffered, not streamed: the citation gate decides below whether the learner ever sees it."
- **`CitationRegistry`.** Records every `[source:<id>]` the application has ever supplied in this conversation, recorded after each `prepare_turn_grounding` call (which now returns the `TurnGrounding`). First record wins; `citation_footer` resolves current-turn IDs first, then registry IDs with a "(from an earlier turn's excerpts)" suffix — so every citation shown to the learner has a visible reference, including citations of earlier turns' excerpts.
- **`invalid_citation_markers(grounding, registry, answer)`.** Lists markers that are neither this turn's evidence nor ever-supplied registry IDs (`[source:none]` is exempt). The check is deliberately **stricter than a raw database lookup**: an ID that exists in the database but was never supplied to this conversation is still fabricated from the model's perspective, and the membership check avoids a database hop per reply.
- **Withhold and reject.** `run_attempt` returns `(session, warnings, response_held, display_buffer)`. Any invalid marker withholds the whole reply and prints one warning per marker ("Withheld the tutor's reply: it cited … which the application never supplied (fabricated reference)."). Only a clean reply is flushed to the terminal, followed by the citation footer.
- **One bounded re-ask.** A withheld reply classifies as `GroundingOutcome::InvalidAcknowledgment`. The application settles attempt-1 record proposals, then appends one application-authored user message telling the model it cited an ID that was never supplied, listing the exact valid markers (current-turn IDs first, then earlier-turn registry IDs), and re-runs the attempt once. If the re-asked reply is still fabricated, it is shown unverified with a warning — honest degradation, no infinite retries. The escalation message is excluded from learner-quote provenance.
