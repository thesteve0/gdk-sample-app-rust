# Visual — Shorten context, keep authority separate

[Rendered PNG](compaction-boundary.png) and [editable, projector-readable SVG](compaction-boundary.svg), 1600 × 1000. Open directly in a browser or SVG editor; no external fonts, scripts, diagram service or build dependency is required. Its text remains editable. This is a **conceptual policy trace**, not captured live output or a claim of summary fidelity.

## Caption

Compaction replaces eligible older working history with one fallible assistant-derived summary. The same Session keeps the original opening and latest two complete genuine learner exchanges, including tool pairs, message IDs and metadata. Authoritative application facts and the learner-authorized persistent record remain distinct. A summary cannot grant write permission, supply genuine learner quotations or support new citations by remembering old source IDs.

## Complete text equivalent / reveal order

1. **Authority remains separate.** Authoritative application state records real provenance, tool IDs, settled decisions and revision. The persistent record uses per-selection consent and narrowly authorized declarations or independently approved proposals. Generated summary text does not rewrite either domain.
2. **Working context before.** The original opening precedes eligible older complete exchanges, a previous summary if present, and the latest two complete genuine learner exchanges. Those recent exchanges include any tool request/result pairs with original IDs and metadata.
3. **Safe boundary.** Local approvals are settled; no pending pair is split. One isolated, tool-free inference prepares summary data without write authority. The application validates the replacement and checks the source revision before applying its replacement Effect. GDK reloads/re-evaluates; it still owns the loop.
4. **Working context after.** In the same Session, the original opening and same protected recent exchanges remain. Eligible older history and any old summary have become **one** new lossy assistant-derived summary. It is data, not instructions or a genuine learner reply. Static instruction, record and tool context remains separate and counted although not expanded in this visual.
5. **Failure and provenance limits.** Failure retains original working history; an already saved local declaration is not rolled back. Summary quotations do not qualify for proposal quotation checks. Only retained real learner replies do; tool output, opening and commands do not. Historical source IDs are reminders, not evidence returned for a new turn: search again before new citations.

## Prediction prompts

- Which arrow changes persistent memory? None: compaction alone has no such authority.
- Why protect a complete exchange rather than just its final answer? Tool pairing, identities and metadata matter for continuity and inspection.
- What does the visual not prove? That the generated summary is faithful, that a learner mastered anything, or that a byte budget equals model-token capacity.

Use the top strip first, then before → boundary → after, then the warning. The SVG can be shown all at once or revealed by zooming/covering regions. The lesson/instructor notes supply resource limits and live fidelity checks; the drawing deliberately avoids a dense full-runtime diagram.
